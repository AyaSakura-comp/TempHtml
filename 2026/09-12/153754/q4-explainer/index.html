01 / 不是原生 BF16 的四倍勝利

部署版 BF16 先把整份 KV 轉成 FP16，再進 FA。繞開這筆額外工作，可以出現很大的比值；不能當成 Q4 硬體天生快四倍。

02 / 不是所有形狀都更快

20K、1 query 比 FP16 快 1.59×；3／4 queries 反而較慢。大 query 數會回退，沒有四倍 prefill 加速。

03 / 跑得快，不等於精度驗收

先前模型 Q4 logit cosine＝0.983334，未過 0.99。合成輸入的速度實驗不能取代模型品質；沒有部署新 kernel。

展開證據、名詞與實驗邊界

我們到底量了什麼？

gfx1151，ROCm 7.2.2；D＝256、16 個 Q heads、2 個 KV heads（GQA＝8）、batch＝1。固定合成輸入和 causal mask；每個 shape／variant 跑 3 個獨立程序，每程序 3 warmup＋10 measured iterations。圖表使用每程序中位數，再取三程序中位數。這裡是 warm-input 微基準，不是冷 cache，也不是模型 tokens/s。

FP16 就是先前報告的 F16；BF16 是另一種 16-bit 格式。兩者的 KV 大小相同，精度／動態範圍不同。Q4_0 每 32 值是 16 bytes payload＋2 bytes scale，總共 18 bytes，對 64 bytes 的儲存比為 3.556×，不是剛好 4×。

VGPR 是每個 SIMD 執行所需的向量寄存器資源；資料放不下時，compiler 把部分暫存放進 per-thread scratch。scratch 請求可能被 cache 接住，不代表每次都碰到 DRAM。圖中的工作站、包裹、路徑與速度皆為教學抽象，不是 chip floorplan、cache miss 計數或逐指令模擬。

Q4 並不是全程 INT4

預設 vec 的 QK 把 Q 量化成 Q8，做整數 dot，再套 scale／offset。softmax 用浮點；P×V 解量化 V 後仍做浮點乘加。圖中的「工作台」包含這些工作，不是只畫一顆 INT4 tensor core。

兩種修正，不要混在一起

① 本頁實測的 tiled：既有 experimental 路徑，讀壓縮 KV，在 kernel 內重建並共用；nq≤4 等條件才啟用。② 單獨限制 PV loop unroll 的新 vec：编譯 scratch 降到零，但第一個候選未過嚴格實作精度門檻，未完成性能驗收。圖表沒有把它列為贏家。

GGML_CUDA_EXPERIMENTAL_GFX1151_Q4_KV_TILED=1 只在隔離測試啟用。正式部署未改。某個 kernel 的資源數不等於它占 wall time 的百分比；本次沒有新的 Q4 動態 ATT／PMC，不能拆出精確 scratch 占時。

仍未證實的目標

比原生、同等最佳化的 BF16-WMMA FA 快 4×。公平的下一步是先建立原生 BF16 control，再測 spill-free GQA tile、融合 Q4 loader 與 QK／PV WMMA。INT4 算術吞吐與 3.556× 儲存壓縮都不能直接推導四倍端到端性能。

資料來源：本機 Q4 FA lab 的 420 個有效樣本；本頁嵌入其中四條路徑、28 種形狀，共 112 個中位數。原實驗的 Q8 不在此圖表中。另有 20 組主 trace 與 2 組 preload 來源驗證 trace。曾作廢重跑 100 個 layout／GPU 隔離存疑樣本，未挑最快值或混入平均。
